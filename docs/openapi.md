# OpenAPI / JSON Schema

`ProblemDetails` object as defined by [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) (formerly [RFC 7807](https://tools.ietf.org/html/rfc7807)). Returned with `Content-Type: application/problem+json`.

The library always emits `type`, `title`, and `status`. `detail`, `instance` and any extension members (RFC 9457 §3.2) are conditional. The optional `code` and `errors` extensions below follow the [SmartBear Problems Registry](https://problems-registry.smartbear.com/) convention and are accepted as extension members but are **not emitted by this library** out of the box.

## OpenAPI 3.0 (YAML)

```yaml
components:
  schemas:
    ProblemDetails:
      type: object
      description: >
        Problem Details object as defined by RFC 9457 (formerly RFC 7807).
        Returned with media type `application/problem+json`.
      required:
        - type
        - title
        - status
      properties:
        type:
          type: string
          format: uri-reference
          maxLength: 1024
          default: 'about:blank'

            A URI reference that identifies the problem type. Per RFC 9457

            "about:blank" when not provided.

          maxLength: 4096

          type: string
          maxLength: 1024

        parameter:
          type: string
          maxLength: 1024

          type: string
```

## Notes

- All members are technically optional in RFC 9457. This schema marks `type`, `title`, and `status` as required because the library always emits them.
- `type` uses `format: uri-reference` (not `uri`) because RFC 9457 explicitly allows relative references; the library emits values like `not-found` when no base URI is configured, plus `about:blank` and absolute URIs.
- Extension members `code` and `errors` follow the [SmartBear Problems Registry](https://problems-registry.smartbear.com/) and Swagger guidance, and are accepted but not emitted by default.
- The `Content-Type` response header MUST be `application/problem+json`.
